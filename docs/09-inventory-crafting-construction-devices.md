# GRAVITY: VOID — инвентарь, крафт, строительство и технологические устройства

## 1. Обзор

Система отвечает за хранение предметов игрока, рецепты крафта, размещение построек (фундаменты, стены, двери, платформы и т.д.) и взаимодействие технологических устройств (генератор, конвейер, турель, грави-якорь и др.). Все три подсистемы интегрированы с существующей ECS-архитектурой, системой гравитации и физикой разрушения.

---

## 2. Инвентарь и предметы

### 2.1 Структура данных

Инвентарь — слотовая система со стаками. Каждый слот содержит либо `ItemStack` (предмет + количество), либо пуст.

```
ItemStack = {
  itemId: string,          // ID предмета (stone_slabs, ferrite_ore, resonit, ...)
  count: number,           // количество в стаке
  maxCount: number,        // максимум в стаке (зависит от предмета)
  quality?: number,        // качество/прочность предмета (0..1, для инструментов)
  tags: string[],          // теги (ore, building_material, food, tool, device)
}

Inventory = {
  slots: ItemStack[],      // фиксированное количество слотов
  maxSlots: number,        // размер инвентаря (зависит от костюма/рюкзака)
  maxWeight: number,       // максимальный переносимый вес (кг)
  currentWeight: number,   // текущий вес (вычисляется из ItemStack × Material.mass)
}
```

Экипировка персонажа — отдельные слоты:
```
Equipment = {
  head?: ItemStack, chest?: ItemStack, hands?: ItemStack, legs?: ItemStack,
  tool?: ItemStack,        // активный инструмент добычи
  backpack?: ItemStack,    // бонус к maxSlots / maxWeight
}
```

### 2.2 Операции с инвентарем

| Операция | Описание |
|----------|----------|
| `addItem(itemId, count)` | Добавить предмет, объединяя с существующим стаком или в пустой слот |
| `removeItem(itemId, count)` | Извлечь предмет из стаков |
| `hasItem(itemId, count)` | Проверка наличия достаточного количества |
| `transfer(fromSlot, toSlot, count)` | Перемещение между слотами инвентаря |
| `dropItem(slot, count, worldPos)` | Выброс предмета в мир (спавн Item-сущности с PhysicsBody) |

Вес предмета считается из `Material.mass` (из системы физики/материалов). Если `currentWeight > maxWeight` — персонаж получает штраф к скорости и не может бегать (интеграция с `CharacterStats.speedPenalty` и `StaminaEnergySystem`).

### 2.3 События инвентаря

- `inventory:item-added` / `inventory:item-removed` — для UI и сохранений
- `inventory:weight-changed` — для пересчёта штрафов персонажа
- `inventory:drop-on-death` — при смерти (Softcore/Hardcore, см. DeathSystem)

## 3. Система крафта

### 3.1 Рецепты крафта

Рецепт описывает, что требуется для создания предмета и каков результат.

```
CraftingRecipe = {
  id: string,                      // уникальный ID рецепта
  name: string,                    // отображаемое название
  inputs: { itemId: string, count: number }[],   // необходимые ресурсы
  energyCost: number,              // затрата энергии на крафт (ЕД)
  craftTime: number,               // время крафта (секунды)
  outputs: { itemId: string, count: number }[],  // результат
  unlockBlueprints: string[],      // чертежи, необходимые для разблокировки
  unlockTechnologies: string[],    // технологии, необходимые для разблокировки
  station?: string,                // требуемая станция (workbench, assembler, ...)
  tags: string[],                  // теги рецепта (building, device, tool, ...)
}
```

### 3.2 Разблокировка рецептов

Рецепт доступен для крафта, если выполнены все условия:
1. Все чертежи из `unlockBlueprints` изучены (хранятся в `PlayerTechnologies.unlockedBlueprints`)
2. Все технологии из `unlockTechnologies` исследованы
3. Если указан `station` — игрок находится рядом с активной станцией крафта

### 3.3 Процесс крафта

```
canCraft(recipe, inventory, player):
    1. Проверка разблокировки (чертежи + технологии + станция)
    2. Проверка ингредиентов: для каждого input — inventory.hasItem(itemId, count)
    3. Проверка энергии: player.CharacterStats.energy >= recipe.energyCost
    4. Проверка места в инвентаре для outputs

craft(recipe, inventory, player, dt):
    1. Тратить энергию пропорционально прогрессу (energyCost / craftTime за секунду)
    2. Накопить прогресс craftProgress += dt
    3. Если craftProgress >= craftTime:
       - Списать ингредиенты из инвентаря
       - Добавить результаты в инвентарь
       - Эмитит событие crafting:completed
```

### 3.4 Примеры рецептов

| Рецепт | Входы | Энергия | Время | Разблокировка |
|--------|-------|---------|-------|---------------|
| Каменная плита | stone × 2 | 5 | 1.0 | Чертеж: Основы строительства |
| Железный пруток | ferrite_ore × 2 | 10 | 3.0 | Чертеж: Обработка металла |
| Гравитационный якорь | resonit × 3, ferrite_ingot × 5, biovolume × 2 | 50 | 10.0 | Чертеж: Грави-технологии I |
| Конвейер | ferrite_ingot × 3, biovolume × 1 | 15 | 5.0 | Чертеж: Логистика |
| Турель | ferrite_ingot × 8, resonit × 1 | 30 | 8.0 | Чертеж: Оборона |

## 4. Строительство баз

### 4.1 Строительные элементы

| Элемент | Описание | Опора | Масса | Прочность |
|---------|----------|-------|-------|-----------|
| Фундамент | Базовое основание здания | Земля / другой фундамент | 50 кг | 10000 |
| Стена | Вертикальная перегородка | Фундамент или стена | 30 кг | 6000 |
| Потолок | Горизонтальная перекрытие | Стена или фундамент | 40 кг | 8000 |
| Дверь | Проход через стену | Стена | 20 кг | 4000 |
| Лестница | Вертикальный переход | Стены / фундамент | 15 кг | 3000 |
| Платформа | Горизонтальная плоскость | Фундамент или балка | 35 кг | 7000 |
| Хранилище | Контейнер для предметов | Фундамент | 60 кг | 5000 |
| Защита (башня укрытия) | Укрытие от урона | Фундамент | 45 кг | 12000 |

### 4.2 Логика размещения

**Режимы размещения:**
- **Снаппинг по сетке (Grid Snap):** постройки привязываются к сетке чанков/тайлов. Режим по умолчанию для фундаментов, стен, потолков.
- **Свободное размещение (Free Placement):** постройка может быть установлена в произвольной точке с коллизионной проверкой. Режим для декоративных элементов и 일부 устройств.

**Призрачное превью (Ghost Preview):**
- Полупрозрачная копия постройки под курсором
- Цвет: зелёный — место валидно, красный — невалидно (нет опоры, коллизия с другим объектом, за пределами зоны строительства)

**Проверка валидности места:**
1. Нет коллизии с существующими физическими телами (Matter.js query)
2. Для элементов с `requiresSupport = true` — есть поддерживающая постройка или грунт рядом
3. В радиусе действия зоны строительства (если ограничена)
4. У игрока достаточно ресурсов в инвентаре

### 4.3 Структурная целостность и гравитация

Каждая постройка имеет **структурную целостность** — цепочку соединений от фундамента до элемента.

```
StructuralIntegrity = {
  integrity: number,           // 0.0 … 1.0 (1.0 = целая)
  anchored: boolean,           // закреплена ли на фундаменте с Гравитационным Якорем
  supportedBy: number[],       // ID сущностей, которые держат эту постройку
  supports: number[],          // ID сущностей, которые эта постройка держит
}
```

**Правила при изменении вектора гравитации:**
1. Если постройка закреплена **Гравитационным Якорем** (`GravityAnchor` активен) — она сохраняет позицию и ориентацию независимо от изменения гравитации.
2. Если постройка **не закреплена** и гравитация меняется:
   - Проверяется путь от постройки до ближайшего якоря через цепочку `supports`/`supportedBy`.
   - Если путь есть — постройка переориентируется относительно нового «пола» (стенка может стать полом и наоборот), сохраняя соединения.
   - Если пути нет — постройка теряет целостность (`integrity = 0`), разрушается и превращается в обломки (`debris` с физикой Matter.js).
3. При обычной гравитации (без изменений) постройки с разорванной цепочкой поддержки обрушаются (кирпич без стены под собой падает).

**Пример:** Игрок меняет гравитацию на «вверх». Стена без якоря и без пути к фундаменту с якорем отрывается и падает в новое направление гравитации.

## 5. Технологические устройства

### 5.1 Список устройств

| Устройство | Функция | Энергия | Выходы |
|------------|---------|---------|--------|
| **Генератор энергии** | Производит энергию из топлива (биогель, уголь) | — | Энергия в сеть |
| **Гравитационный якорь** | Удерживает постройки и объекты при смене гравитации | Потребляет | Поле стабильности гравитации |
| **Стабилизатор** | Защищает зону от гравитационных аномалий | Потребляет | Поле стабильности |
| **Сканер** | Сканирует территорию, revealing ресурсы и аномалии | Потребляет | Данные сканирования |
| **Дрон** | Автономная добыча и доставка | Потребляет (заряд) | Предметы на базу |
| **Турель** | Автоматическая оборона | Потребляет | Урон по врагам |
| **Конвейер** | Транспортирует предметы между блоками | Потребляет (мало) | Предметы по линии |
| **Лифт** | Перемещает игроков и предметы вертикально | Потребляет | Перемещение сущностей |
| **Грави-ловушка** | Меняет локальную гравитацию в зоне | Потребляет | Зона изменённой гравитации |

### 5.2 Архитектура взаимодействия устройств

Устройства объединяются в **цепи (сети)** через два канала:

#### 5.2.1 Энергетическая сеть (Energy Network)

```
EnergyNode = {
  entity: number,              // сущность устройства
  type: 'producer' | 'consumer' | 'battery',
  powerOutput: number,         // ЭД/сек (для производителей)
  powerConsumption: number,    // ЭД/сек (для потребителей)
  storedEnergy: number,        // для аккумуляторов
  connectedNodes: number[],    // ID связанных устройств (через провода или adjacent)
}
```

- **Генератор** — производитель. Выдаёт энергию в сеть.
- **Турель, бур, сканер, конвейер** — потребители. Забирают энергию из сети.
- **Батарея** — накапливает избыток, отдаёт при дефиците.
- Устройства conectятся автоматически, если находятся в радиусе `energyLinkRadius` (например, 3 тайла) или соединены кабелем (строительный элемент «кабель»).

Баланс сети каждую секунду:
```
netPower = Σ producers.output - Σ consumers.consumption
if netPower < 0:
    батареи разряжаются, чтобы покрыть дефицит
    если батареи пусты — 소비тели отключаются по приоритету
if netPower > 0:
    избыток заряжает батареи
```

#### 5.2.2 Логистическая сеть (Item Transport)

```
ItemRoute = {
  fromEntity: number,          // источник (хранилище, конвейер, бур)
  toEntity: number,            // приёмник (хранилище, верстак, бур)
  itemId: string,              // какой предмет транспортировать
  maxRate: number,             // предметов в секунду
  currentLoad: number,         // предметов в пути
}
```

- **Конвейер** — перемещает предметы от источника к приёмнику по линии конвейеров.
- **Хранилище** — источник и приёмник одновременно.
- **Автоматический бур** — источник руды, отправляет на конвейер.
- **Дрон** — автономный transporteur между складом и точкой добычи (не требует конвейера).

Транспортировка реализуется через событие `item:transport-request` в `EventBus`. `DeviceSystem` проверяет доступность пути (цепочку конвейеров) и перемещает `ItemStack` между инвентарями устройств.

### 5.3 Пример цепи

```
Автоматический бур → Конвейер → Конвейер → Хранилище
     ↓                           ↓
 Энергия от Генератора        Энергия от Генератора
     ↓                           ↓
Гравитационный якорь (держит всю постройку при смене гравитации)
```

## 6. Интеграция с существующими системами

| Система | Интеграция |
|---------|------------|
| `GravitySystem` | Гравитационный якорь переопределяет гравитацию для связанных построек; без якоря постройки обрушаются при смене вектора |
| `PhysicsSystem` | Постройки — физические тела Matter.js; разрушенные постройки становятся `debris` |
| `MiningSystem` | Добытые ресурсы попадают в инвентарь или на конвейер |
| `StaminaEnergySystem` | Устройства потребляют энергию из персонажной или сетевой энергии |
| `DeathSystem` | Инвентарь дропается при смерти (Softcore/Hardcore) |
| `SaveSystem` | Состояние инвентаря, поставленных построек, сетей устройств сохраняется в IndexedDB |
