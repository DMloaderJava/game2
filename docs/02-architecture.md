# GRAVITY: VOID — модульная архитектура (ECS)

## 1. Выбранная парадигма: ECS (Entity–Component–System)

Игра построена на **ECS**, а не на классической иерархии объектов (GameObject → Sprite → Enemy). Это позволяет добавлять биомы, способности, предметы и типы ИИ как независимые плагины, не переписывая ядро.

### Основные понятия

| Понятие | Что это | Пример |
|---------|---------|--------|
| **Entity (Сущность)** | Простой числовой идентификатор. Никаких методов, никакой логики. | `#42` — игрок, `#427` — астероид, `#931` — факел |
| **Component (Компонент)** | Чистые данные, без методов. Описывает *что* есть у сущности. | `Transform {x, y, rotation}`, `PhysicsBody {matterBody}`, `Renderable {texture}` |
| **System (Система)** | Логика, которая работает над всеми сущнаниями, обладающими набором компонентов. | `PhysicsSystem` обновляет все сущности с `Transform + PhysicsBody` |
| **World (Мир)** | Контейнер: хранит сущности, компоненты, системы и шину событий. Единственная точка входа в игру |

### Цикл кадра (фиксированный шаг 60 FPS + интерполированный рендер)

```
1. InputSystem      — читает клавиатуру/мышь/тач → пишет Intent-компоненты
2. AISystem         — принимает решения мобов → Command-компоненты
3. PhysicsSystem    — шаг Matter.js, гравитационные зоны, коллизии
4. ConstructionSystem — размещение/уничтожение построек
5. InventorySystem  — крафт, экипировка, перенос предметов
6. EventSystem      — катастрофы (бури, обрушения, метеориты)
7. RenderSystem     — PixiJS отрисовка (только чтение компонентов)
8. SaveSystem       — автосохранение (по таймеру / событию)
```

Все системы регистрируются в `World` с явным порядком выполнения. Порядок настраивается в конфиге, а не хардкодится в ядре.

## 2. Модульность и плагины

Ядро игры не знает ни про «Лесный биом», ни про «Телепортацию», нипро «Зомби». Всё это — плагины:

```
Plugin = {
  name: string,
  version: string,
  install(world: World, services: Services): void
}
```

Плагин при установке:
1. Регистрирует свои компоненты (`world.registerComponent(...)`),
2. Добавляет свои системы (`world.addSystem(...)`),
3. Подписывается на события (`eventBus.on(...)`),
4. Регистрирует префабы (шаблоны сущностей) — например, `prefabs.register("void-meteor", {...})`.

**Примеры плагинов:**
- `biomes/void-biome` — изменяет гравитацию, цвет фона, спавн объектов,
- `abilities/teleport` — способность игрока с коoldown-компонентом,
- `items/ore-vantablack` — новый предмет с текстурой и рецептом крафта,
- `ai/hunter-ai` — система поведения преследователя с поиском пути.

Ядро не меняется при добавлении любого плагина.

## 3. Сервисы (уровень инфраструктуры)

Системы не вызывают PixiJS и Matter.js напрямую — они общаются через сервисы. Это упрощает замену движка и тестирование без рендеринга.

| Сервис | Ответственность |
|--------|-----------------|
| `PhysicsService` | Обёртка над Matter.js Engine/World: создание тел, гравитация, фильтры коллизий, отладочная отрисовка |
| `RenderService` | Обёртка над PixiJS Application: сцена, слои, камера, текстуры, спрайты |
| `AudioService` | Обёртка над Howler.js: звуки, музыка, позиционное аудио |
| `StorageService` | IndexedDB: сохранения, загрузки, автосохранение, миграция версий |
| `InputService` | Сырые события ввода → абстрактные действия (`move`, `jump`, `build`, `attack`) |

Системы получают сервисы через DI-контейнер при создании.

---

## 4. Взаимодействие модулей (коротко)

Системы **не ссылаются друг на друга напрямую**. Обмен информацией идёт через:
1. **Общий ECS World** — системы читают/пишут компоненты сущностей,
2. **EventBus** —Pub/Sub для слабо связанных событий (например, `OnEntityDied`, `OnGravityStormStart`),
3. **Intent/Command компоненты** — ввод и ИИ пишут намерения, а физика/строительство их исполняют.

Подробная схема — в `docs/04-interaction.md`.
