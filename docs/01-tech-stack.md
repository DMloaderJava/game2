# GRAVITY: VOID — выбор технологий

## 1. Общие требования к стеку

| Требование | Что это значит для выбора |
|------------|---------------------------|
| **Веб-браузер** | Игра запускается без установки, только HTML/JS/WASM, деплой на статический хостинг |
| **Много физических объектов** | Нужна пакетная отрисовка (batching), эффективный wide-phase коллизий, спящие тела (sleeping bodies) |
| **Модульность** | Биомы, способности, предметы и ИИ подключаются как плагины, не трогая ядро |
| **Жанр Survival/Sandbox/RPG/Physics** | Нужен инвентарь, крафт, постройка, кастомная гравитация на тело, сохранения больших миров |

## 2. Итоговый стек

| Слой | Технология | Версия | Обоснование |
|------|------------|--------|-------------|
| **Язык** | TypeScript | 5.x (strict) | Типизация защищает от регрессий при развитии модальности; ECS без типов быстро становится не поддерживаемым |
| **Сборка / dev-сервер** | Vite | 5.x | Мгновенный горячий перезапуск, нативная поддержка TS, оптимизированная сборка для браузера |
| **Менеджер пакетов** | pnpm | 8.x | Быстрая установка, жёсткая детерминированность (`pnpm-lock.yaml`) |
| **Рендеринг (2D)** | PixiJS | v8 | Легкий WebGL-рендерер с автоматическим спрайт-батчингом, полный контроль над каждой сущностью, слоями и камерой. Лёже и прозрачнее Phaser 3 для кастомной ECS-архитектуры |
| **Физика** | Matter.js | latest | 2D rigid-body: гравитация на каждое тело, sleeping, broadphase, комозитные тела, пользовательские коллизионные фильтры — идеально для «Гравитации в пустоте» |
| **Звук** | Howler.js | latest | Обёртка над Web Audio API: позиционное/пространственное аудио, стриминг музыки, gestión одновременно звучащих эффектов |
| **Хранение в браузере** | IndexedDB (обёртка `idb` или Dexie.js) | — | Большие файлы сохранений мира, транзакции, офлайн-работа. `localStorage` — только настройки пользователя (звук, клавиши) |
| **Сериализация сохранений** | JSON + LZ-string (сжатие) | — | Сохранения миров с тысячами объектов сжимаются в 5–10 раз; JSON легко мигрировать между версиями |
| **ECS** | Собственный легковесный ECS на TypeScript | — | Полный контроль над сигнатурами компонентов и порядком систем; никакой навязанной иерархии объектов |
| **Сборка модулей/плагинов** | ES-модули + Vite плагины | — | Биомы, способности, предметы, ИИ регистрируются в ядре через явный интерфейс плагина |
| **Деплой** | Vercel или GitHub Pages | — | Статический сайт, CI/CD из репозитория, глобальный CDN |

## 3. Почему не другие варианты

| Альтернатива | Почему отвергнута |
|--------------|-------------------|
| **Phaser 3** | Отличный движок, но его иерархия Game Objects и встроенные системы мешают чистой ECS; PixiJS даёт тот же рендер с меньшим накладным расходом |
| **Three.js** | Избыточен для чистого 2D side-scroller, больше памяти, сложнее оптимизировать тысячи спрайтов |
| **Planck.js (Box2D port)** | Физика быстрее Matter.js, но встроенная поддержка пользовательской гравитации на тело и события коллизий хуже — для игры про гравитацию это критично |
| **Matter.js + был бы Canvas 2D API** | Canvas 2D не справится с thousand-object батчингом; WebGL через PixiJS — must have |
| **localStorage для сохранений** | Лимит ~5 МБ, синхронная запись блокирует главный поток — неприемлемо для песочницы с большим миром |

## 4. Стек для разработки (инструментарий)

- Линтер/форматтер: ESLint + Prettier
- Типы: `tsc --noEmit` в pre-commit / CI
- Тесты: Vitest (юнит-тесты систем ECS без рендеринга)
- Отладка физики: Matter.js DebugRenderer (только в dev-сборке)
- Мониторинг производительности: FPS/мс с帧-таймингом, график количества активных тел
